# 项目经验笔记

## 本项目的适配规则

先读[项目规范](../../../AGENTS.md)、[文档规范](../../../Docs/AGENTS.md)、[Agent Notes 格式](../../notes/README.md)和[笔记维护规则](../../notes/AGENTS.md)。以下通用方法服从这些项目规则，格式和类别只在上述文件维护。

- 非平凡改动必须在同一提交或 PR 中新增或更新 Agent Note；不能用“没有新经验”跳过该要求。纯机械或局部改动可以不写。
- `.agents/notes/` 是随项目公开的决策记录，按现有生命周期和类别存放；先检索同主题，不另建工作日志或进度索引。
- 本机环境、授权记录与原始取证留在 `.agents/private/` 或 `.pi/`，公开笔记不包含私有值，也不链接这些目录。
- 写完从仓库根运行 `uv run --no-project python scripts/check-docs.py`。检查通过只表示文档检查通过，不代替代码测试或真机验收。

写给下一次处理相关任务、没有本轮聊天上下文的执行者。笔记的价值是让它识别容易误判的条件，采取有依据的行动。

## 主动维护的时机

由 AI 主动判断，不等待用户说“记一下”。按工作事件触发，不按固定时间、对话轮数或笔记数量执行：

- **开工时**：先检索与当前任务相关的旧经验，再决定实现或排查方式。
- **形成重要结论时**：确认了不明显的原因、选定或否决了有长期影响的方案、核实旧笔记已失效，或用户纠正了可复用的项目判断，立即评估是否值得记录。符合下节标准时，在转入下一阶段前最小化更新原主题，不积攒到整个长任务结束。
- **准备交接或收尾时**：检查本轮是否仍有只留在聊天中的重要条件、理由和验证依据。需要保留的及时归位；有笔记更新时，在交付中附简短说明与链接。

原因未明的报错和未经核实的猜测不急着写成经验；未解决事项放项目已有任务记录，并保留不确定性。当前为只读任务或没有目标位置写入授权时，只报告候选经验。没有新经验就不写，用户无需逐条批准已授权范围内的维护。

## 先定位，再检索

1. 从当前任务确定项目根目录；不要相对本技能的安装目录寻找项目文件。跨仓任务分别确认各仓的归属。
2. 读取适用的 AGENTS.md 和现有笔记入口，沿用其目录、格式、文档分工与公开规则。项目明确共享其他仓库的笔记时，使用该入口；读取不自动授权跨仓写入。
3. 无既有约定时，默认使用项目根下的 `.agents/notes/README.md`。目录不存在就说明尚无笔记；首次确有值得记录的经验、且当前任务已授权编辑时，才创建简短索引和相关笔记。不预先建立 WORK、复盘或归档框架。
4. 按任务的模块、症状、错误信息或机制检索，只读命中的记录；需要依据时再沿链接查代码、测试或复盘，不全量加载历史。
5. 核对会影响本次操作的结论是否仍适用。历史成功不是本轮验证，旧限制也不能未经核实就成为永久禁令。证据不足时保留不确定性。

## 决定是否记录

先问：下次处理类似任务，缺少这条信息，是否容易误判或重复付出排查成本？

- 值得记：非显然的触发条件、直觉做法为何失败、容易被破坏的约束、可能再次被尝试的被拒方案，以及可靠但不直观的处理方法。
- 成功方案和重要取舍只要能指导后续选择，同样值得保留；不能为了强调坑点而编造失败、根因或备选方案。
- 不必记：普通成功、命令流水、代码已清楚表达的步骤、没有后续指导价值的一次性报错。没有新经验就不新增文件。

## 写给下次执行者

先搜索同主题，优先更新原记录。用具体机制或症状命名，开头说明适用场景与行动提醒，再按需要保留：

- **条件与影响**：什么情况下会触发，哪种看似合理的操作会出错，后果是什么。
- **原因与处理**：证据支持什么解释，应如何处理，哪些方案确实试过或被否决。
- **依据与范围**：链接代码、测试或复盘，给出必要验证入口；区分事实、推测和待验证项，说明适用范围及重新考虑的条件。

这些是信息要求，不是必须填满的栏目；项目有自己的格式时遵循它。篇幅够后续行动即可，不复制会话过程或通用教程。配置留在原维护位置，笔记链接过去并解释重要理由。

## 更新与收尾

- 新证据、范围变化或防护改进归入原主题。重要决定反转时，保留原理由与替代关系，不把过去改写成从未发生。
- 合并、删除或修正前保留仍有效的独有信息，并修复索引与引用；不按时间或篇数机械清理。只处理本次相关记录。
- 当前进度、稳定用法、架构设计与普通执行结果，分别归项目已有的对应文档或交付说明。已有复盘能指导行动时链接即可，不重复根因与经过。
- 笔记留在所属项目，不将私有正文汇总到全局技能，也不借此修改工具自身的记忆系统。不记录密钥、私人材料或完整日志；遵守项目的跟踪、提交与公开规则。新增 `.gitignore` 不会移除已跟踪内容和历史。
- 只读任务只查证和报告；已授权开发或维护范围内直接更新，无需逐条请示。写笔记不代替修复、测试或用户验收。
