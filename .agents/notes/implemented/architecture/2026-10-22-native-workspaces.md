# Agent Note: 原生会话与工作区

Status: implemented

## 问题

Pi 的原生 newSession/fork/switchSession 会替换当前 CLI，不能用来保留电脑进程并在目标工作区开第二个原生会话。让网关执行 SDK continueWorkspace 则会创建另一个 AgentSession，违背桥接单写者约束。

## 决定

- 手机沿用工作区的 Fork、打开已有与新建空会话。Fork 由源扩展在同一同步回调中执行公开 SessionManager.forkFrom，确认持久树与 live 条目一致，再按 live 叶子和模型/思考设置追加目标记录。只写新目标；源 CLI、源文件、电脑草稿保留。源忙、队列、压缩或控制操作未结束时拒绝复制。
- 目标存储目录根据网关配置与目标 cwd 通过公开 SessionManager.create 计算，仅构造内存管理器，不造 AgentSession。目标通过 --session 文件启动原生 Pi，再检查真实快照中的模型/思考；不可用时明确失败，不静默换模型。原 CLI 的私有启动覆盖和内存扩展任务不迁移。
- 两侧独立持久回执保护复制与启动。Fork 完整 checkpoint 后才公布目标；结果未知时只查询同一目标，不盲目复制或启动另一个。进程恰在目标文件完成与回执之间退出时可能留保守冲突，保留源和副本供人工核对，不猜测认领或自动删除。公开返回值不包含目标会话文件路径。
- 新空会话首页仍在首条发送时创建。先校验项目信任、持久占位，再用公开 --session-id 启动指定原生 ID，不手写空 header。原生新快照先建立实例/代际，首条 submitted 必须匹配操作 ID 和已建立身份；启动前无会话的拒绝只认自己的操作 ID。超时或明确拒绝保留稿件，信任确认后由用户再次发送。
- 会话级工作区列表从在线原生 descriptor 的 cwd 读 Git；Fork 与列表的成功/错误绑定操作或查询 ID、源会话、实例和代际。目录信任与操作日志查询不访问原生会话，独立关联；桥接操作日志查询不得调用 SDK worktreeStatus 的恢复路径。切换模式中的原生写入也不能回退 SDK。

## 考虑过的方案

直接用新原生进程的 --session 指向不存在文件会生成另一个随机 ID，手机无法可靠对账。用新 SDK 句柄预先写 header、从网关跨进程读写源 live 状态，或把 fork ACK 当成目标已经可用，都不能证明原生会话与运行器一致。

## 影响

契约由网关 PROTOCOL §4.38 维护。网关的真实 SessionManager、路由与启动日志回归，以及隔离真实 Pi CLI 的复制/目标启动/桌面草稿检查分别验证不同边界；没有真机、真实网络和 Provider 证据时仍待验。共享层关联回归覆盖快照前 ACK、错操作与错代际响应；原有 SDK 工作区语义保持，见[工作区行为](../feature/2026-10-18-mobile-worktree-actions.md)。
