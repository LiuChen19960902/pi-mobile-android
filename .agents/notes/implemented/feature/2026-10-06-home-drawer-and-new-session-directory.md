# Agent Note: 首页、会话抽屉与新会话目录

Status: implemented

## 问题

旧首页把会话列表、搜索和新建放在一个滚动页里，固定区在低高度屏上会遮住列表；发送第一条消息后页面元素整体替换，看起来像换了一页。新会话的工作目录也有多个来源：首页选择、当前会话 cwd、抽屉里的目录筛选，曾出现“选了 A 目录却在 B 中新建”。

## 决定

### 页面结构

- 首页与会话共用同一个页面和输入区。未绑定会话、没有内容或可见的发送预览、没有历史加载或错误时才显示中央品牌；欢迎装饰、加载、错误和空态互斥，不叠加显示。背景、输入区和工作区行在发送前后常驻。
- 会话管理在左侧抽屉：搜索在顶部、设置与网关状态在底部固定，列表使用剩余高度滚动。抽屉为不透明面板，宽度为屏宽 82%、最多 360dp，不设下限，窄分屏也能露出主页面。
- 新建只做本地导航，首条消息发送时才创建 Pi 会话；`sent` 已经绑定会话，不再重复导航或清空新建状态。

### 新会话目录

- 显示目录与实际发送的 cwd 共用 `newSessionDirectoryPath`。从已有会话按加号时，当前会话的 cwd 是最新意图，清除更早的显式选择；进入空白页后再改选的目录优先，再按加号保留该选择。目录状态只在当前进程保留。
- 抽屉的目录药丸 `selectedDirectory` 只是局部筛选，不自动进入首页目录状态。点新建时把该药丸的完整 cwd 传入 `prepareNewSession`；标签只显示末级名称，同名目录以完整路径为身份。“全部”和缺少 cwd 的分组没有可继承目录，回退到首页选择或当前会话目录。
- 检查要核对首条 message 实际带的 cwd，而不只看目录文案。

### 弹层与按钮

- 模型 / 档位和网关菜单以卡片本身为定位边界，默认与入口间隔 4dp，阴影不占布局尺寸；模型列表在 4dp 时容易误触，单独用 16dp。安全区由宿主 `LocalWindowInfo.containerSize` 与 `WindowInsets.safeDrawing` 在同一窗口坐标下求得，包含系统栏和 IME，用于限制卡片尺寸并滚动。Popup 禁用平台二次裁剪和挪位后必须保留这些显式约束；不为某台设备硬编码偏移。
- 按钮的可见面与触控区分开：例如发送 / 停止的可见色块 34dp、外层 42dp，“回到底部”可见面 38dp、外层 48dp。缩小可见面时不缩小触控区和输入区高度测量；透明外层关闭默认 indication，避免方形涟漪超出圆角。
- 输入区先测量工具栏，再把剩余高度给可滚动的正文区（附件、输入框、联想、照片候选），键盘、多行文字和选图同时出现时滚动正文而不压扁按钮。

## 考虑过的方案

**旧首页改用 stickyHeader 固定搜索与新建。** 固定区约 350dp，低高度屏上遮住列表。

**发送后切换为另一套背景和布局。** 用户感知为换页。

**半透明抽屉。** 会透出主页文字，影响可读性。

**历史显式目录选择始终优先。** 导致“选 A → 打开 B 会话 → 加号”仍落在 A。

## 影响

- 目录选择不跨进程保留。
- 弹层位置依赖窗口安全区计算，换设备时需要检查键盘与系统栏组合。

## 核对入口

- `prepareNewSession`、`newSessionDirectoryPath`、会话抽屉的 `selectedDirectory`、`AnchoredPopupMenu` / FineCat 弹层组件、`ComposerLayout`。
