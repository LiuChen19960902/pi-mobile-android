# Agent Note: 六位配对码共享失败预算

Status: implemented

## 问题

完整配对文本适合扫码或复制，不适合手输。直接截短原秘密会降低登记设备所需的猜测成本；只限制某个猜测值、安装 ID 或来源地址，攻击者能通过换值绕过。

## 决定

网关在原有长配对秘密之外签发六位数字别名，保留开头的 0。每个进程只有一个活动短码窗口，最多两分钟，所有有效格式的错误猜测共用五次预算。新签发替换旧短码；第五次错误销毁对应长码，任一方式领取成功同时消费长短码。过期和失败仅返回通用未授权，不开放猜码反馈。期限与使用方式集中在[安全说明](../../../../SECURITY.md#2-凭据)。

长期 token 的熵、存储和重连协议保持独立，六位数字不能作为 Bearer 或 pi-auth 凭据。短码只交给用户指定地址，不向其他候选网关回落；手机不持久化短码。持久入口在收到 paired 后才更新，配对被拒绝不改用原有 token 重试。确认后先删除旧 token、再保存新地址及新 token，跨存储失败以需要重配收尾，避免旧 token 与未确认地址绑定。扫码和长文本继续可用，以兼容旧网关。

## 考虑过的方案

**直接把长期凭据改成短码。** 会把远程操作电脑的长期权限降为可枚举数字，拒绝采用。

**按客户端限流。** 未鉴权客户端能更换安装 ID，来源也可能经代理合并；采用窗口共享预算，接受同网段恶意尝试导致窗口耗尽的可用性代价。网络隔离仍然是前提。

## 影响

六位码输错耗尽后必须由电脑重新签发，手机不能自行续期。旧网关仍可通过扫码或配对文本使用；新表单不会把短码发送到其他候选地址。

## 核对入口

- 网关 `tests/short-pairing.test.ts` 和 `tests/server.test.ts`：期限、失败耗尽、长短码互斥领取、真实握手与 token 重连。
- `GatewayRuntimeIntegrationTest`：开头的 0、目标地址隔离、非法输入无连接副作用。
- `GatewayConformanceTest.shortCodePairsThroughProductionTransportAndReconnectsWithStoredToken`：真实网关与手机生产 transport 的跨仓核对，不调用真实模型。
