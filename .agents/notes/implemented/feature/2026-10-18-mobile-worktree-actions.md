# Agent Note: Mobile Worktree 的动作与失败结果

Status: implemented

## 问题

手机选择目录既可能是在准备新会话，也可能是在另一个工作区继续已有对话。把它们合为一种切换会误移当前草稿、复制空会话，或在结果未知时重复生成会话。Git worktree 与 Pi 会话树也是独立概念，不能用 Tree 跳转代替工具执行目录的改变。

## 决定

首页选择只设下一条新会话的目标；会话内“新建空白会话”回首页，首条消息才创建；“Fork 当前会话”在目标建立独立上下文，保留源会话。首页目标与当前会话目录分别持有。“打开已有会话”列出目标目录的会话，由用户选择；对话页默认继续当前对话，首页默认新建。普通打开复用`selectSession`，源草稿留在源会话，目标恢复自己的草稿与图片；不合并历史，不自动选最近一条，源任务忙碌时也可浏览其他会话。列表来自真实 Git，每次打开和手动刷新重扫，主工作区按 Git 路径标识识别。 创建需要能解析为提交的基点；只有 `git init` 的空仓库尚无可用 `HEAD`。没有可达提交与基点写错分别提示，不自动为用户创建初始提交。

每次主动跨目录继续都是独立操作，可能留下多条同名会话；回到某一条原会话应选“打开已有会话”。只在同一操作的重试中复用副本，不按标题或首条消息去重。

Pi SDK 1.3.0 的 `SessionManager.forkFrom` 复制完整树且保持 entry ID。网关在空闲、无压缩和队列时取得活动 leaf，在目标调用公开 `branch`，再追加实际模型与思考设置。这样保留当前路径，也让重开目标会话落在该路径；源文件不改写，目标 AGENTS、Skills、配置和工具 cwd 重新加载。模型不可用时明确失败，不借用 SDK 默认模型回落。

会话列表按完整cwd匹配，不包含子目录或相似前缀。全局会话Reducer会合并并保留旧摘要，因此工作区面板只允许选择本次`sessions`应答中实际存在的ID；隐藏项沿用抽屉规则。`sessions`没有请求代号，队列替换或旧请求超时不能认领当前面板的等待；本地读取限时按面板代次收尾，成功帧只更新全局列表，不直接导航。

项目资源遵循公开 `ProjectTrustStore`。目标未信任时由手机明确确认，只保存该规范路径的信任；支持该能力的网关上，首页目录确认和另开会话也先检查。没有信任确认就不能加载目标项目资源。

写操作以随机 UUID 关联并记入宿主私有 journal，同参数重放返回同结果，异参数拒绝。已完整落盘的目标副本可继续确认；明确失败的重试复用该副本。创建成功后继续失败，只重试继续。目录选择失败只重试选择；打开已有会话失败回候选列表，不能借用继续动作的重试而隐式复制对话。结果未知保持查询态，不重新执行写操作；关闭确认卡可留在源会话继续编辑，迟到结果不再搬走这些输入。

手机收到匹配操作、源会话和导航代次的成功结果后，迁移当前草稿的文字、图片、URI 和准备 token 一次，不自动发送。过期结果不改变新页面。待确认记录按宿主凭据摘要隔离，只持久化查询字段，不保存正文、附件或凭据；进程重启后只查询，用户自行打开已就绪会话。

## 考虑过的方案

**选择目录统一切换。** 会把首页目标选择误当成延续已有会话，因此保留三种动作。

**目标有会话就自动恢复最近一条。** 同一个工作区可有多项独立任务，会误开另一段上下文；保留明确的已有会话入口与列表选择，不覆盖或合并目标历史。

**SDK 的单分支 fork。** 它会重新组织单条路径，不能保留完整树；采用完整文件 fork 和公开追加 API，不导入内部模块或直接改写 JSONL。

**只修改运行时 cwd。** 无法保证会话头、资源和重开后的目录一致，因此建立目标独立运行器；源运行器保留，启动失败不需要假装已经回滚。

**只在列表禁用忙碌操作。** 创建并切换、目录树和结果卡重试也能延续对话，必须共用最后一道门槛；仅创建和另开不受忙碌限制。

**未知结果按失败重试。** 可能复制第二份会话，因此将查询和重试明确分开。创建失败与已创建但继续失败分别呈现。

## 影响

源会话保留为历史；Git 不自动带入未提交、未跟踪或忽略文件，不执行提交、stash、合并或删除工作区。第三方扩展私有内存任务不承诺迁移。持久化确认信息不能恢复进程退出后原本仅在内存里的草稿；未能确认的操作不自动重放。进程恰在 fork 落盘与完整 checkpoint 之间中断时可能持续 unknown；保留文件与源会话，不把不确定状态当成功，也不自动删副本。Git 创建禁用仓库 hooks，避免在项目信任确认前执行它们。
