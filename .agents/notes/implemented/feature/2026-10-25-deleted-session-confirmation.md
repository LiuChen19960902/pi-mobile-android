# Agent Note: 会话删除必须有文件缺失的独立确认

Status: implemented

## 问题

Pi 的会话列表发现是尽力而为：目录或单文件读取失败会变成缺项。把远端列表整体替换到手机，会在权限错误、短暂断网或实例切换时丢掉仍有效的条目；只做合并又会永久保留电脑已删除的会话。

## 决定

- 复用列表请求附带同一配对网关已返回的路径，由网关显式确认删除。客户端不从空列表、普通 not-found 或请求失败推断删除；旧网关保留合并行为。协议字段归网关 PROTOCOL 的 sessions 节维护。
- 目标文件必须明确缺失，父目录仍可访问，重新枚举的 Pi 会话文件须能由 SDK 识别；已移到新路径、存在 SDK 句柄或在线桥接描述符时不确认。普通 JSONL 日志不算 Pi 会话；首条非空记录明确是非 session JSON 对象时可跳过，否则读取失败或身份无法判别仍保留。扫描不完整时宁可暂留条目，不自动关闭实例。
- 确认后从抽屉移除，但当前选择、标题、缓存正文和草稿保留，发送同时由界面、门面与 Runtime 阻断。历史重拉可能先清缓冲，因此保留最近一次重拉前的正文，只在删除被确认时作为回退；正常历史重载语义不变。
- 同 ID 的文件重新被发现时解除确认；当前页重新订阅并补拉历史，新页成功前保留缓存。重新配对清除旧网关的路径和确认。手机的隐藏名单仍只影响本地展示，不承担宿主删除。
- 删除闸门可以阻止迟到内容投影，但已经消费 lane 的请求仍须向门面交付终态，否则会留下无法释放的发送 token。跳过已删除目标的排队请求属于本地拒绝，不按传输失败回收整条连接。

## 考虑过的方案

直接按列表差集清理会误判扫描失败；永远只合并则无法收敛删除。两者都不能表达文件是否仍存在，因此使用独立的删除确认。

要求每个 JSONL 都被 SDK 识别也不可行：宿主目录允许存放非 Pi 日志，会全局阻断无关会话的清理。文件后缀只用于枚举，首记录的类型才决定是否属于会话范围；判别读取有上限，不加载整份历史。

## 影响

Pi CLI 只禁止删除自身当前打开的会话，不保护其他进程持有的文件。本机制不处理外部删除仍被运行实例持有的文件，也不承诺恢复它后续写出的历史。未加载桥接扩展的 CLI 无法由网关确认在线。

回归入口：GatewayConformanceTest 的真实隔离文件删除链路、SharedMobileStoreTest 的缺项保留、AndroidGatewayProjectionTest 的重拉后缓存回退、AndroidSharedStateHolderTest 的草稿与发送保护。根界面的设备用例需要实际运行，编译不能替代真机验收。
