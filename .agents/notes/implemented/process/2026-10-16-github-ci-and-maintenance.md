# Agent Note: GitHub 持续集成与仓库协作

Status: implemented

## 问题

本地测试结果不能阻止后续未检查的合入；跨仓库一致性测试缺少网关时还会跳过。公开协作需要可重复的检查、最小权限和清楚的反馈入口。

## 决定

- 两仓通过PR协作，使用Squash合并并自动删除已合并分支；主分支保护在仓库方案支持时启用，CI检查实际跑通后才列为必过项。个人维护阶段不强制其他人的审批。
- [Android CI](../../../../.github/workflows/ci.yml)运行文档与脚本检查、两组JVM测试和debug构建；[结果校验器](../../../../scripts/check-ci-test-results.py)拒绝缺失、失败、错误或跳过的报告，并要求GatewayConformanceTest实际运行。
- Android CI检出固定提交的配套网关并安装依赖；更新协议基线时同步更新该提交。网关仍私有时，GATEWAY_CI_SSH_KEY仅用于读取该网关仓，禁止写入；公开后可移除这项凭据。工作流不保存检出凭据，也不使用真实Provider或发布签名。
- 两仓CI在GitHub托管Linux上运行，任务有超时且同分支新任务取消旧任务。网关按文件串行测试，避免不同文件的监听端口互相干扰。
- Actions默认只读；使用固定提交的官方Actions及明确允许的uv安装Action。依赖更新每周分组提交PR，不自动合并。
- Issues和PR模板收集复现、版本与实际验证，提醒分享前脱敏；漏洞按安全策略私下报告。Wiki和Discussions暂不启用。

## 考虑过的方案

**只在贡献指南中列出测试命令。** 不能确认每次合入都执行过，也不能拦截缺少网关而被跳过的一致性测试。

**把个人的广权限GitHub凭据作为跨仓检出密钥。** 权限超出读取一个配套仓的需要；选择可单独撤销、只读且限定单仓的deploy key。

**把正式签名和真实模型配置加入普通PR检查。** 测试只需要合成配置和隔离网关，正式发布与普通检查分开。

## 影响

自动检查不代表真机接受，也不验证所有宿主平台。私有仓的分支保护和部分安全功能受GitHub方案限制，必须核对实际生效状态。跨仓固定提交需要在协议兼容关系变化时明确维护。
