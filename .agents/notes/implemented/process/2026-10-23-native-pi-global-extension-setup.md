# Agent Note: 原生 Pi 接入按普通启动配置全局扩展

Status: implemented

## 问题

一次用 `pi -e` 启动的实例能被手机发现，不能证明下一次普通 `pi` 启动也会加载桥接。用户日常直接运行 `pi`，只提供单次启动命令会漏掉全局配置。手机仍能列出该实例的历史文件，因此“看得到会话但提示原生实例离线”容易被误判为连接或状态刷新缺陷。

## 决定

- 安装入口使用 Pi 原生 `pi install` 把仓内桥接子包登记到全局 `packages`，保留其他配置与已装包；不另写 settings 安装器，也不把网关根包注册成扩展。路径与卸载步骤由[网关安装说明](https://github.com/LiuChen19960902/pi-mobile-gateway#连接电脑上的原生-pi)维护，手机仓库的[开始使用](../../../../README.md#开始使用)只链接该入口。
- 已运行的实例在空闲时 `/reload`；包安装或手机模式切换不会直接为既有进程加载扩展。安装成功只证明包已登记，还要检查真实加载错误及无 `-e` 的普通启动。
- 旧 `extensions` 与 package 指向同一真实入口时由 Pi 去重；`pi remove` 只移除包登记，不清旧手工路径。卸载与迁移说明不能假称旧入口已消失。
- 桥接所用思考档位函数从 `@earendil-works/pi-ai` 的公开根入口导入。较早 Pi SDK 加载器会把 `/models` 子路径错误拼到根别名后，包发现成功仍可能工厂加载失败；不能仅用 bundled CLI 成功替代 SDK 资源加载检查。
- 排查先区分磁盘会话与在线实例：核对目标进程、实际配置目录/桥接根、扩展注册描述符和可读快照。普通启动验收必须包含一次未传 `-e` 的新进程；注册成功与手机实际续聊分别验证。
- 实例在线不等于全部操作可用。自定义编辑器归属与停止/取队列边界沿用[桥接记录](../architecture/2026-10-20-mobile-bridge-mode.md)，不得为了上线标记而覆盖用户编辑器或绕过队列保护。

## 考虑过的方案

**要求用户手动追加全局入口。** 旧安装方式能持久加载，但要求自行编辑 JSON，且卸载不受包管理器管理；标准入口交给 Pi 自带包管理，旧登记保留可追溯迁移说明。

**只把 `pi -e` 当安装说明。** 它适合单次验证和排错，但只作用于当前启动，用户下一次直接运行 `pi` 时扩展不会因那次参数自动加载。保留该方式作为临时入口，不作为日常使用的前提。

## 影响

- 同一配置目录下的后续普通 Pi 启动都会加载所登记入口；仓库移动后需要更新路径。其他配置目录或其他机器需要分别配置。
- 不改 Pi 源码，也不从磁盘文件推断实例在线；只读历史与接管运行中的 CLI 仍有不同条件。
- 全局加载保持第三方编辑器原有归属，不能据此承诺队列取回、携带队列恢复的停止等操作在所有编辑器下都可用，公开边界见[兼容说明](../../../../Docs/pi-compatibility.md)。

## 核对入口

- Pi CLI `install` / `list` / `remove`、公开 `DefaultResourceLoader` / `SettingsManager` 与 CLI `/reload`。
- 网关桥接扩展 `resolveBridgeRoot`、`writeDescriptor`、`start`、`editorAvailable`。
- 普通启动的注册快照只证明实例接入；真实模型调用、手机交互与用户确认需要分别核对。
