# Agent Note: 开源发布使用无历史快照

Status: implemented

## 问题

项目在私有仓库中开发了很久，已跟踪文件和旧提交里有内部笔记、评审报告、agent 运行记录，提交正文和截图边缘也可能带个人信息。`.gitignore` 不会移除已跟踪的文件，也不会清理旧提交，所以不能直接把开发仓改为公开。

## 决定

- 首次公开从筛选后的文件快照发布，不带旧 Git 历史：私有开发仓中的导出脚本（不随公开源码发布）导出两个仓库当前工作区中已跟踪和未被忽略的新增文件，按规则排除内部资料，输出不含 `.git`。导出前对源仓和输出目录都先 `resolve()` 再检查包含关系，相邻网关目录可能是符号链接，否则输出可能落进真实工作树。
- 公开仓库之后独立开发。私有仓的改动只能按文件补丁选择性迁入，不能 merge 私有分支或推送全部 refs，否则旧历史会重新进入公开仓库。首个公开提交使用明确的公开署名和邮箱，不继承全局 Git 身份；noreply 邮箱只隐藏真实邮箱，仍关联账号。
- 公开副本上分别做凭据扫描、个人标记与链接核对、媒体文件检查：
  - 凭据扫描零命中不代表截图或普通文字里没有个人信息，截图要打开逐张看完整字段和边缘；遮挡用不透明覆盖并重新编码。
  - JPEG 在 EOI 结束标记之后可能附带数据，只清 EXIF 不够。
  - PNG 的生成来源信息可能在 `caBX`（C2PA/JUMBF）块，只查 `tEXt`/`eXIf` 不够。不改画面时保留 IHDR/IDAT 并核对图像数据。
  - 检查对象是最终导出的全部媒体，不只是 README 引用的图片；原始宣传图和提示词由导出规则精确排除，只发布去元数据的副本。
- 在导出副本上验证构建与测试，而不是在开发仓里。
- 源码快照干净不代表从私有仓构建的 APK 也干净：AGP 会把开发仓提交写进 `META-INF/version-control-info.textproto`。Release 构建设置 `vcsInfo.include = false`，签名后检查实际 APK，不在签名后手改 ZIP。Release 未配置发布签名时只产出 unsigned 包，不回退到 debug 签名。签名与命名规则见 [Docs/releasing.md](../../../../Docs/releasing.md)。
- 源码归档清理 owner、ID、mtime 和扩展属性，只保留必要的相对路径。公开文件、APK 和归档三者分别核对。

## 考虑过的方案

**把开发仓直接改为公开，靠 `.gitignore` 和删除文件隐藏内部资料。** 旧提交仍可访问，被删除的文件和提交正文都会公开。

**用历史重写工具清理旧提交后公开。** 需要逐个提交确认清理结果，范围大且容易漏；开发历史本身对协作者价值不大，私有保留即可。

## 影响

- 公开仓库没有开发历史，`git blame` 只能追到首个公开提交；早期设计理由靠 Agent Notes 保留。
- 私有仓与公开仓之后会分叉，迁移改动需要手工挑选文件并重新检查隐私。
- 发布前的隐私检查是人工流程，没有自动门禁覆盖截图内容。

## 核对入口

- `androidApp/build.gradle.kts` 中 Release 的 `vcsInfo.include`。
- 检查命令：`git status --short -- <文件>` 判断是否已跟踪（`git diff` 无输出可能只是文件未跟踪）。
