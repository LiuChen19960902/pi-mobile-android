# Agent Note: 验证结论的层级与证据要求

Status: implemented

## 问题

开发中多次出现“结论比证据大”：设备用例只编译就写成通过；整组全绿被当成逐条单跑的证据；日志早于最后一次改码；校验器的豁免分支恒真；判别力探针自己没有生效。跨仓库测试缺少网关时会自动跳过，也曾被读成通过。

## 决定

### 结论按层级写

验证结论分开写各自实际执行的层级：

1. 静态核对（阅读源码、grep 符号）；
2. JVM 测试（`:shared:testAndroidHostTest`、`:androidApp:testDebugUnitTest`）；
3. 设备用例实际运行（instrument）；
4. 真实网关与 Pi 调用；
5. 真机人工检查。

只编译的设备用例不能写成通过；被跳过的跨仓库测试要在报告中列出 skipped，不能算通过。Gradle 的 UP-TO-DATE / 缓存结果不是本次进程调用的证据。

### 证据要求

- 宣称做了逐条单跑，就要有每个方法一份原始日志和退出码；整组运行中的第 N 个不是隔离验证。
- 最终证据必须产生于最后一次改码之后：运行前记录改动源文件与产物的哈希，运行后在设备上核对已安装包的哈希，把“本地构建 → 设备安装 → 运行”串成一条链。
- 一个检查器“全部通过”只覆盖登记成用例的条件；没登记的要求不会被计分。读结论时先看它列出的“无法验证的部分”。
- 校验器中的任何豁免分支都要有一条能打红它的反例测试；“如果把这个引用改成不存在的名字，它会红吗？”
- 判别力探针本身要先确认变异生效（打印被改的行，或让反例数量对上）；取退出码用 `cmd >out; rc=$?`，不要在管道后取 `$?`（拿到的是最后一个命令的退出码）。

### 测试隔离

- 测试不读写真实的 `~/.pi`。子进程的 `PI_CODING_AGENT_DIR` 指向空临时目录；外层环境中设置的空 `PI_CODING_AGENT_DIR` 也会覆盖 fixture 的临时 HOME，跨仓库测试启动子进程时移除该变量，让 fixture 的 HOME 生效。
- 不能以“读取了真实用户配置后没有变化”断言“没有污染配置”。
- 不依赖沙箱阻止写入来假定隔离；夹具显式提供临时的 agentDir、models 和状态文件。

### 结论的依据

- 独立审查的 finding 要依据实际签名和分支核对，不采纳基于假设的推测（例如“如果某处失败也递增 revision”）；跨版本的编译疑虑以项目实际的 Kotlin / Compose 版本与成功编译为准。
- 多个排查者得出相同结论，仍需源码和实际产物支持。
