# AGENTS.md — 文档规范

本文件规定文档放在哪里、怎么写、如何检查。Agent Note 的目录与格式见 [.agents/notes/README.md](../.agents/notes/README.md)。改动任何文档后运行：

```sh
uv run --no-project python scripts/check-docs.py
```

## 一事一处

每个事实只在负责它的文档里写一次，其他地方链接过去。

| 文档 | 负责的内容 | 不写在这里 |
| --- | --- | --- |
| 根 [AGENTS.md](../AGENTS.md) | 每次会话都需要的常驻规则，每条一到三行并链接详细文档 | 机制说明、示例、排查过程、从其他文档复述的内容 |
| 子目录 `AGENTS.md`（本文件、[.agents/notes/AGENTS.md](../.agents/notes/AGENTS.md)） | 该目录特有的规则 | 根 AGENTS.md 已有的规则 |
| [README.md](../README.md) | 产品能做什么、如何安装和开始使用 | 开发流程、设计理由 |
| [ARCHITECTURE.md](../ARCHITECTURE.md) | 分层、模块职责、主要数据流 | 决策理由（→ Agent Note）、逐类细节（→ 源码注释） |
| [CONTRIBUTING.md](../CONTRIBUTING.md) | 环境、构建、测试、提交、CI 定义 | 运行时行为、设计理由 |
| [SECURITY.md](../SECURITY.md)、[gateway-connect.md](gateway-connect.md) | 安全模型、连接拓扑与排错 | 实现历史 |
| [pi-compatibility.md](pi-compatibility.md) | 支持哪些 Pi 能力、边界在哪 | 具体实现机制（→ Agent Note） |
| [releasing.md](releasing.md)、[third-party-notices.md](third-party-notices.md) | 签名、发布文件与命名、第三方许可 | 本机分发方式 |
| [Agent Notes](../.agents/notes/README.md) | 为什么这样做、放弃了什么、违背后如何重犯 | 使用说明、计划清单、排查流水账 |
| [CHANGELOG.md](../CHANGELOG.md) | 每个版本的对外变更 | 设计理由 |
| 网关仓库 `PROTOCOL.md` | 帧类型、字段、错误码、能力宣告 | 客户端实现 |

放置原则：用户怎么用 → README；结构 → ARCHITECTURE；理由与取舍 → Agent Note；协议 → 网关 PROTOCOL；常驻规则 → 根 AGENTS.md 并链接理由。

## 写作规则

- **写现状，不写变更史。** 描述当前的机制和行为，不写“以前”“现在改为”“不再”。历史只出现在 CHANGELOG、提交记录和 Agent Note 的 `考虑过的方案` 中。
- **只写公开信息。** 不写本机路径、IP、主机名、设备型号、账号、凭据或私人会话内容；示例地址用 `<LAN_IP>`、`<TS_HOST>` 等记号并说明获取方法。不链接不公开的内部资料。
- **用相对 Markdown 链接引用仓库内文件**，不写纯文件名或编号，便于检查和移动。
- **区分已验证与推断。** 写清验证层级（静态核对、JVM 测试、设备用例实际运行、真实网关与 Pi 调用、真机检查）；未验证的不写成结论。
- **直接说明谁做了什么、在什么条件下、造成什么结果。** 不用比喻，不堆术语；需要定位时附准确的符号名。
- 正文中文，标识符、命令、协议字段和错误原文保持英文。
- 代码注释写约束和原因，不复述代码、不记录排查过程；注释密度与周边一致。
- 文档随代码改动一起更新：行为、配置、连接或安全相关的变化同步更新对应文档。

## 废话清单

检查任何文档时查找并删除：

- 同一规则写在多处：搜一句有特征的原话，只留一处，其余改为链接。
- 历史叙述：“以前”“现在”“改为”“曾经”、构建号、任务编号、会话编号。改写为当前事实，需要理由时链接 Agent Note。
- 实现状态标注：“已完成”“待验收”“未来会……”。状态会过期，以代码和发布记录为准。
- 手工维护的清单（测试数量、文件列表、版本列表），当源码或命令能给出时。
- 推理过程：逐步的实现叙述、测试操作流水、对显而易见分支的证明。保留结论和理由。
- 段落墙：一个段落装多条规则和括号补充。拆开或把细节移到负责的文档。
- 强调泛滥：到处加粗等于没有重点。只强调改变行为的那一句。

## 字数预算

常驻规范文件的上限登记在 `scripts/check-docs.py` 的 `BUDGETS` 中（中文按字、英文按词计）。超限时按顺序处理：

1. 把属于其他文档的内容迁走，必要时留一行链接；
2. 精简属于这里但可以更短的内容；
3. 确实需要空间时才提高上限，并在提交说明中写明理由。

## 检查的范围与豁免

`scripts/check-docs.py` 检查：Agent Note 的目录、文件名与格式；公开文档的相对链接和 `#锚点`，以及是否指向不公开的路径；公开文档中的 IP、本机路径、tailnet 主机名、邮箱和凭据形态；规范文件与 Agent Notes 中的内部编号和开发过程用词；字数预算；个人补充规则文件未被提交。

确属合理的命中（例如说明规则时引用被禁止的词）在同一行末尾加 `<!-- check-docs: allow <规则名> -->`，规则名见报错中的方括号。豁免只针对该行，不要整段关闭检查。
